## 一、專題目標：多代理系統

### 1.1　定義

**這門課說的「多代理系統」，要同時滿足三個條件。**

| | 條件 | 內容 |
|---|---|---|
| **一** | **分工** | 一件任務由**兩個以上的角色**完成。每個角色有自己的職責與邊界——看得到什麼、**明確看不到什麼**、可使用哪些工具 |
| **二** | **獨立驗證** | **至少有一個角色，其職責為查核另一個角色的結論。** 且該角色必須**自行取得證據**：不得讀取對方提供的證據，也不得複述對方的說法 |
| **三** | **處理不一致** | 兩方結論不同時，系統須有**明確的後續處理**：再查一輪、交第三個角色裁決，或標記為「需人工覆核」。**不得逕行採信其中一方** |

三個條件缺一不可。少了條件二，它是流水線；少了條件三，它是兩個各自陳述的模型。

這門課要你們練的就是這幾件事：**角色怎麼劃分、各自看得到什麼、由誰查核誰、
結論不一致時怎麼辦、系統壞掉時怎麼查。**

### 1.2　舉例

用你們 HW1–HW4 用過的那批三級規章當例子。**這個題材不能當期末題目，這裡只是示範形態：**

| 步驟 | 內容 |
|---|---|
| 輸入 | 「某生 114 學年度入學、碩士班，欲至他校修習一門本校未開設的課程，本學期最多可修幾學分？」 |
| **執行代理** | 檢索規章 → 答「上限為當學期學分的三分之一」，依據校際選課實施辦法第四條 |
| **查核代理** | **自行產生查詢**檢索條文 → 取得第四條**第二項**：該三分之一僅適用學士班，碩士班「得由各系所另訂之」，而系修業規則查無該規定 |
| 不一致 | 兩方結論不同 → 再查一輪；仍不一致 → 標記「需人工覆核」並附兩方依據 |
| 輸出 | 結論「資訊不足（規定未載）」＋ 依據「第四條第二項」＋ 信心值 |

**從這個例子就看得出來，條件二為什麼要求「自行取得證據」**：
如果查核代理沿用執行代理給的第四條去查，它只會看到那個三分之一，
然後同意一個錯的結論。**查錯方向的查核，比沒有查核更危險**——因為它會背書。

### 1.3　「審件」是一種形態，不是規格

上例屬於「審件」形態：輸入一份個案，輸出**判定（可／不可／需補件）＋ 依據 ＋ 信心值**。
一張報帳單、一件招標案、一份實習申請，都是同一種結構。

**六個推薦領域都是這個形態**，因為這類任務本身就有「規章」當證據、「個案」當輸入，
查核代理一定找得到東西可查——這是它最容易成立的原因。

**但審件是例子，不是規格。** 自訂領域的規定見第三節。

### 1.4　驗收的層級

```
  L3   產出正式的意見書 / 報告 / 通知                ← 加分項
  L2   文件上傳、影像辨識，免除人工輸入              ← 加分項
  L1   對話追問：「為什麼不行？」「補件後呢？」        ← 加分項
 ────────────────────────────────────────────────
  L0   任務輸入 → 結論 ＋ 依據 ＋ 信心值，且經獨立查核  ← 驗收對象
```

**L0 是驗收的對象。L0 未完成者，L1 以上不列入驗收。**

> **最常見的誤解是 L1。** 對話介面是最熟悉的形態，容易在一開始就投入於介面，
> 到期末才發現 L0 的**獨立查核**並未實際運作。

## 二、期末驗收標準

這一段我現在就給你們，是為了讓你們有十週時間照這條路徑設計系統，
而不是等到期末才知道我要驗什麼。

> 使用者提交一個任務 → **執行代理**輸出結論與其依據 →
> **查核代理獨立重查**：自行產生查詢、取得自己的證據，驗證該依據是否存在、
> 是否支持該結論 → 兩者不一致時觸發第二輪或升級 →
> 系統輸出最終結論、依據與信心值。
>
> **此路徑須於期末展示現場實際執行**；其餘分支（L1 以上）得以設計文件與模擬軌跡呈現。

「依據」視領域而定，可以是**條號、段落 id 或資料來源**。

### 「獨立重查」的兩層要求

1. **不得僅複述執行代理的輸出文字。** 重讀同一段內容不構成查核。
2. **查詢必須由查核代理自行產生**，不得由程式以執行代理的輸出拼接而成。
   期末現場須能出示**查核代理實際發出的查詢原文**與其取得的證據 id。

> **為什麼連檢索起點都要獨立**：拿執行代理給的依據當查詢起點，本身就是一種不獨立。
> 我自己實測過：當執行代理引錯依據時，沿用那個依據去查的查核代理會整題查錯方向、
> 找不到反證，最後同意一個錯的結論。

## 三、題目選擇：推薦領域與自訂領域

### 3.1　推薦領域

見 `六題型說明卡.md`。卡片上寫的是**我查到的規章來源、個案出處，以及我已經知道的難點**。
六者難度並不相同，每張卡的最後一欄就是可行性。

> **卡片不等於背書。** 它告訴你規章在哪、難點在哪，
> 但**個案拿不拿得到，要你們自己在 §5 舉證**。
> 其中一個領域，我還沒查到公開的個案來源，卡片上有註明。

### 3.2　三項要件（適用所有題目）

不論你們選推薦領域或自訂領域，題目都要同時符合三項要件，
否則多代理這件事就只剩形式。

| 要件 | 要說明的 | 排除的情形 |
|---|---|---|
| **要件一　證據可取得** | 有一批確實取得的文件或資料，查核代理能從其中**獨立檢索到證據** | 無語料可依據的題目 |
| **要件二　結論可追溯** | 每個結論都指得出依據**哪一份、哪一段** | 無法指出依據的生成式應用 |
| **要件三　結論有不一致的可能** | 查核代理**在什麼情況下會判定「不成立」**，須舉一個具體情況 | 僅能附和、不具否決可能的查核角色 |

**要件三是實質門檻。** 若查核代理永遠只會表示同意，它便不構成查核。

兩種題目的差別只在報備：

| | 三項要件 | 10/28 當場說明 |
|---|---|---|
| 推薦領域 | 適用（要件一的舉證寫在 §5） | 不必 |
| 自訂領域 | 適用 | **必須** |

> ### ⚠ 自訂領域須於 **10/28 課堂當場提出**
>
> 三項要件當場審核。**不受理 11/09 才提出的新領域**——該時點已無調整空間，
> 亦來不及更換題目。推薦領域不在此限。

### 3.3　個案的倫理規定（適用所有題目）

**一、個案不得涉及可識別的真實個人。**
必須使用真實文件時，須**去識別化並以代號表示**（文件 A／文件 B），
不列姓名、學號，也不列可直接辨識的題名或單位。

**二、系統的判定對象限於「文件是否符合規範」。**
**不得產出對特定個人的指控性判定**——抄襲、違規、失職、不適任等皆屬此類。
判「這份文件符不符合 X 規範」可以；判「這個人有沒有抄」不可以。

**三、本條適用所有題目，含自訂領域。**
報帳單含姓名、實習申請含學號、隱私政策初篩天生涉及個人資料——
這不是某一個領域的問題。

> **為什麼是限縮判定對象，而不是乾脆禁止你們用真實文件**：
> 問題出在判定的內容，不在個案是真是假。
> 公開文件去識別化之後拿來用，既能滿足「證據已實際取得」，也不會留下對個人的指控。

### 3.4　不得選用的題材

**「系所修業路徑規劃」不得作為期末專題題目。**

理由為公平性：該題材是 HW1–HW4 的共用練習場，語料為本系實際的三級規章。
若予採用，選此題材的組別將帶著十週整理完成的語料、調校過的檢索參數與既有評測集
進入期末，其餘各組須從零開始。

**因此參考範例的內容無法沿用。** 範例刻意採用練習場題材示範，格式可參照，內容不可。

## 八、§6 多代理架構的填寫要求

**預設角色配置**（直接採用就好，不會因此吃虧；這個配置課堂上示範過）：

```
執行代理（提出結論與依據） → 查核代理（自行取得證據驗證） → 裁決／收斂
```

**這一節我會看的是以下四個問題：**

1. 要設置**幾個**角色？為何不是更少或更多？
