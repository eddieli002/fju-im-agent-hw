## 你們最後要做出什麼

**一個多代理系統。** 它的定義有三個條件，缺一不可：

| | 條件 | 說的是什麼 |
|---|---|---|
| 一 | **分工** | 一件任務由兩個以上的角色完成，各有職責與邊界（看得到什麼、**明確看不到什麼**）|
| 二 | **獨立驗證** | 至少一個角色的職責是查核另一個角色的結論，而且**自己去取得證據** |
| 三 | **處理不一致** | 兩邊結論不同時要有明確的下一步，**不能沉默地採信其中一邊** |

完整定義與一個走完整條路徑的例子，見 `期中提案說明.md` 第一節。

**下面六個領域都是同一種最容易成立的形態：審件。**
丟一個案子進去（一張報帳單、一件招標案、一份實習申請），
輸出**判定 ＋ 依據 ＋ 信心值**。這種任務天生就有「規章」當證據、「個案」當輸入，
所以查核代理一定找得到東西可查。**但審件是例子，不是規格**——見本節最後。

可以往上堆疊——對話追問、文件上傳、產出正式意見書——但那些都是加分。
**驗收的是最底下那一層**：任務進去、結論出來、依據指得出來，而且**經過獨立查核**。

```
  L3   產出正式的審查意見書 / 退件通知           ← 加分
  L2   文件上傳、拍照辨識，不用手打               ← 加分
  L1   對話追問：「為什麼不過？」「補件呢？」      ← 加分
 ────────────────────────────────────────────
  L0   個案進 → 判定 ＋ 依據條號 ＋ 信心值        ← 驗收的就是這一層
```

**L0 是驗收的對象。L0 未完成者，L1 以上不列入驗收。**

> **最常見的誤解是 L1。** 對話介面是大家最熟悉的形態，很容易一開始就投入在介面上，
> 到期末才發現 L0 的**獨立重查**並未實際運作。

### 三項要件（適用所有題目）

不論選推薦領域或自訂領域，題目都要同時符合三項要件，否則多代理這件事就只剩形式。
**自訂領域另須於 10/28 課堂當場提出**（見下方）。

| 要件 | 要說明的 | 排除的情形 |
|---|---|---|
| **要件一　證據可取得** | 有一批確實取得的文件或資料，查核代理能從其中**獨立檢索到證據** | 無語料可依據的題目 |
| **要件二　結論可追溯** | 每個結論都指得出依據**哪一份、哪一段** | 無法指出依據的生成式應用 |
| **要件三　結論有不一致的可能** | 查核代理**在什麼情況下會判定「不成立」**，請舉一個具體情況 | 僅能附和、不具否決可能的查核角色 |

**要件三是實質門檻。** 若查核代理永遠只會表示同意，它便不構成查核。

> ⚠ **自訂領域必須於 10/28 課堂當場提出**，三項要件當場審核。
> **不受理 11/09 才提出的新領域**——該時點已無調整空間。
> 下列六個推薦領域不在此限，可直接選用。

**挑領域時請用這個標準想像**：這個領域丟進去的「一個任務」長什麼樣？

## 共通背景：六個領域是同一種結構

六者皆為「**依規章對個案做出有依據的判定**」，所以都能長出審核型多代理系統：

```
個案 → 主張代理（判定 ＋ 依據條號）→ 查核代理（獨立重查該條號）
     → 不一致時第二輪或升級 → 最終判定 ＋ 依據 ＋ 信心值
```

差別只在「規章長什麼樣」與「個案好不好取得」。

**兩種語料，缺一不可**：

| | 是什麼 | 沒有它會怎樣 |
|---|---|---|
| **規章** | 判定的依據，條文 | 系統無法給出「依據條號」，退化成瞎猜 |
| **個案** | 被判定的對象 | 系統無事可做，只能空轉 |

**六個領域的規章都拿得到，差別全在個案。** 挑領域時請特別看這一欄。

## 規章要綁在哪一個機構？——**這一題比你想的重要**

下面每張卡片的「規章來源」欄，給的都是**國家法規**或**別的學校**的公開版本
（全國法規資料庫、國科會、教育部，以及台大、成大、北科大等）。

**這是刻意的。** 你們做的不是「輔大專用的審件機器」，而是
**「一套規章 ＋ 一批個案 → 有依據的判定」** 這個通用問題。
規章綁在哪個機構是你們自己的設計決定，而**那個決定要說得出理由**。

### 為什麼建議至少綁兩套來源

**因為單一機構的規章，多半不需要多代理。**

一套規章、一個個案、一條路徑 → 查一次就有答案 → 那是檢索，不是審核。
你們要做的系統有主張、查核、裁決三個角色，**而它們只有在「說法會打架」時才有意義**。

規章之間會打架的地方，通常長這樣：

| 型態 | 練習場裡的真實例子（你們手上就有） |
|---|---|
| **上位授權、下位沒訂** | 《校際選課實施辦法》第四條第一項給學士班訂了上限（當學期學分的三分之一），第二項卻寫「**碩、博士班學生之規定得由各系（所）另訂之**」——而系修業規則裡查不到那條。**問碩士生每學期最多能修幾學分，正解是「規定未載」，不是把三分之一套過去。** |
| **同一機構、不同層級** | 《學位論文印製格式統一規定》只有兩頁，卻出現**五處「由各系所自訂」**（標題方式、註解方式、參考書目格式、參考書目位置、作者簡歷）。校級訂了邊界與字級，其餘丟給系所——**同一份論文可能同時受兩套規範管**。 |
| **同一機構、不同年度版本** | 院級《必選英語授課專業課程規定》同一份文件裡有三段年度分軌：112 學年度起碩士班要修 1 門，104 學年度起那一段**完全沒規範碩士班**。**不指定入學學年度，這一題就無解。** |
| **同一件事、不同機構規定不同** | 這一種練習場裡沒有——因為語料只有一所學校。**而它正是你們最可能遇到的一種**：A 校論文格式要 12 號楷書、B 校要標楷體；APA 第七版 vs IEEE；教育部的要點 vs 各校自訂的辦法。 |

**前三種在 HW1–HW4 的練習場語料裡都出現過**，差別只是那時候規章是我給的，現在要你們自己找。
**第四種要靠你們自己綁兩套來源才會出現**——而它通常是最好處理、也最容易講清楚的一種。

> ⚠ 上面三個例子用的是**練習場的語料**（系所修業路徑規劃）。
> 那個題材**不得作為期末題目**，所以它只能當例子看，不能拿來當你們的題。

### 那輔大自己的版本呢？

**找得到就用，找不到也完全不影響。**

如果你們找得到輔大對應的規定（例如自己系上的實習辦法、研究計畫的核銷規定），
那很好——它會讓你們的個案更貼近真實，而且**和外部版本擺在一起，本身就是一組現成的
「規定衝突」素材**，正好餵給查核代理。

但**不要為了找輔大的版本卡住**。有些內部規定本來就不會公開上網，
那不是你們的問題，也不是這份作業要考的東西。**把力氣花在「這一套規章能不能撐起
一條判定路徑」，不是花在「我一定要找到某一份檔案」。**

### 這一節對提案表的意思

提案表 **§4（依據與判準）** 與 **§5（證據來源與取得方法）** 要寫清楚：

- 你們綁的是**哪一套**規章（機構、文件全名、版次或年度）
- **為什麼是這一套**——不必是最權威的，但要說得出它撐得起你們的判定
- 如果綁了兩套以上，**它們在哪裡會不一致**（那一格可直接用於提案表 §7 的失敗情境）

> **⚠ 「通用」不等於「隨便找」。** §5 檢核的是
> **你實際取得了什麼、能不能重複取得**——不是你講得多抽象。
> 挑定、下載、能展示樣本，這三件事做完才算數。

## 領域 1｜實驗室／研究計畫報帳與核銷稽核

**判定什麼**：一筆支出能不能核銷、要走哪種程序、有沒有超過期限。

| | |
|---|---|
| **判定邏輯特徵** | 核銷期限、單據要件、金額級距 |
| **規章來源** | 國科會《補助專題研究計畫作業要點》與《經費處理原則》（`law.nstc.gov.tw` 公開全文）；各校主計室的核銷作業規定（成大、國體大等校的簡報與要點皆公開上網） |
| **個案來源** | **需自行虛構**。可依規章的禁止項目與金額門檻反推 |
| **三級結構** | 國科會 → 學校主計室 → 系所，層級關係與 HW1–HW4 的練習場同型 |

**已查到的幾條硬判準**（可直接當判定條件）

- 計畫執行期滿後 **3 個月內**辦理經費結報；單據應於期滿後 **15 日內**送主計室
- 採購金額 **15 萬元以上**須製作驗收紀錄，且驗收合格日須在計畫執行期限內
- 交際應酬費、罰款、贈款、捐款、私人用款**一律不得支用**

**預期難點**

1. **各校版本差異大**。國科會是母法，但實際核銷規則在各校主計室，兩者可能不一致——
   這對多代理系統其實是好事（正好是「規定衝突」的來源），但你們要先意識到它存在。
2. 個案要自己編，而編得出「剛好踩線」的個案需要先讀懂規章。

**可行性：🟢 高**——規章層級清楚、判準硬、與課堂練習場同構。個案須自編是唯一成本。

## 領域 2｜資訊安全政策遵循檢查

**判定什麼**：某機關的資安作為是否符合其責任等級應辦事項。

| | |
|---|---|
| **判定邏輯特徵** | 存取控制矩陣、個資法要件 |
| **規章來源** | 《資通安全管理法》、施行細則、《資通安全責任等級分級辦法》（全國法規資料庫全文公開）；數位發展部資通安全署法規專區 |
| **個案來源** | **⚠ 最大的問題所在，見下** |

**已查到的結構**

- 責任等級分 **A、B、C、D、E 五級**，依業務重要性、機關層級、資料類型與系統規模判定
- 應辦事項涵蓋管理面、技術面、認知訓練面三類
- C 級以上：遠端存取內部網路或資訊系統須進行監控

**預期難點**

1. **個案極難取得。** 這一題的「個案」是某機關的資安維護計畫或稽核報告，
   而那是敏感文件，不會公開。你們拿不到真的。
2. 若改為自行虛構，虛構的難度也高——要編出一份像樣的資安維護計畫，
   本身就需要資安專業，容易編成「為了觸發規則而編」的假個案。
3. 規章敘述抽象（「應建立」「應定期」），轉成可執行判準的落差比其他領域大。

**可行性：🟡 中低**——規章最好拿，但**個案我還沒查到公開的來源**。
選此領域者，§5 須具體寫出你們的個案從哪裡取得。

> **若仍想選這一題**，建議把範圍縮小到一個具體且有公開範本的子題，
> 例如「資安事件通報時限判定」，而不要做全面的遵循檢查。
> 選之前請先找到你們的個案來源，並在 11/11 提案時說明。

## 領域 3｜校外實習／建教合作資格審查

**判定什麼**：某生的實習申請是否符合資格、時數與保險要件。

| | |
|---|---|
| **判定邏輯特徵** | 時數、保險、資格門檻 |
| **規章來源** | 教育部《補助技專校院開設校外實習課程作業要點》（`edu.law.moe.gov.tw` 公開）；教育部《大專校院推動學生校外實習課程作業參考手冊》；台大、成大、北科大等校的校外實習辦法皆公開上網<br>⚠ 其中《補助技專校院開設校外實習課程作業要點》**已於 105-03-23 廢止**（頁面仍讀得到，標題冠「廢」）。**不要拿它當依據**，請改用現行的《大專校院推動學生校外實習課程作業參考手冊》115 年 1 月版。 |
| **個案來源** | **自行虛構，但極好編**——一份申請表就是一個個案 |

**已查到的幾條硬判準**

- **1 學分至多 80 小時**；單一學期不超過 **720 小時**；畢業總時數不宜超過 **1440 小時**
- 學校**應為實習學生投保**大專校院校外實習學生團體意外保險
- 實習分「**一般型**」（純學生身分）與「**工作型**」（兼具學生與勞工身分），兩者法律關係不同
- 醫護科系另有學分門檻：四技／五專須 20 學分以上，二技／二專須 9 學分以上（⚠ **此門檻僅見於已廢止的要點，不要引用**）
- 學校須先檢核機構是否符合法定要件，簽約後始得推薦學生前往

**預期難點**

1. **「一般型／工作型」的區分是這一題的核心難點**，也是最好的多代理素材——
   判定結果會決定適用勞基法與否，主張與查核代理很容易在這裡分歧。
2. 各校辦法細節不同，要選定一所學校作為判定基準。

**可行性：🟢 高**——判準量化（時數、學分數）、個案好編、有一個真正需要推理的分歧點。

## 領域 4｜論文格式與學術倫理預審

**判定什麼**：一份論文稿是否符合格式規範與原創性要求。

| | |
|---|---|
| **判定邏輯特徵** | 格式規範、引用規範、相似度判準 |
| **規章來源** | 各校學位論文格式規範（台大、台南大學、逢甲等校皆提供公開檔案）；教育部學術倫理資源網《深化學位論文原創性與預防抄襲的校園指引》 |
| **個案來源** | **⚠ 有倫理風險，見下** |

**已查到的幾條硬判準**

- 相似度：**排除引言、參考文獻、目錄及附件後，單篇應低於 10%**
- 格式：摘要不超過 3 頁、A4 白色 80 磅紙、中文 12 號楷書／英文 12 號 Times New Roman、
  中文 1.5 倍行距／英文雙倍行距、繳交圖書館 2 冊
- 繳交前須完成 Turnitin 比對並簽署學術倫理暨原創性比對聲明書

**預期難點**

1. **個案的使用方式見 `期中提案說明.md` 3.3**（適用所有領域的倫理規定）。
   可使用**已公開**的學位論文，但須**去識別化、以代號表示**，
   且判定對象限於格式與引用規範的合規性。
   ⚠ 國圖臺灣博碩士論文系統**部分論文的電子全文須作者授權**，挑選時要先確認下載得到。
2. **格式審查其實不太需要推理**（字型、行距、頁數是機械比對）。
   **真正值得判定的是引用格式與參考書目是否符合所選規範**——
   而**多校或多期刊的規範之間必然衝突**（A 校 12 號楷書 vs B 校標楷體；APA vs IEEE），
   那才是需要主張、查核、裁決的地方。

**可行性：🟡 中**——規章極好拿，但需要刻意設計才不會退化成格式檢查器。

## 領域 5｜政府採購與招標合規檢核

**判定什麼**：一件採購案的金額級距、應採何種招標方式、程序有無瑕疵。

| | |
|---|---|
| **判定邏輯特徵** | 金額級距決定招標方式，**邏輯最硬** |
| **規章來源** | 《政府採購法》、《中央機關未達公告金額採購招標辦法》（全國法規資料庫全文公開）；行政院公共工程委員會法規系統 |
| **個案來源** | **🟢 六題之中唯一有大量公開真實個案的** |

### 個案來源是這一題的決定性優勢

**政府電子採購網**（`web.pcc.gov.tw`）——全國各機關的招標與決標公告，
**免申請、免登入即可瀏覽與電子領標**。另有政府資料開放平臺（`data.gov.tw`）
的政府電子採購資料集。

也就是說，**這是唯一一題你們可以拿真實案件當個案的**。
其餘五題的個案都得自己編。

### 另有一個 MCP 介面（非官方，選用，**不特別推薦**）

`https://api.tobid.tw/mcp` 是第三方把同一批政府電子採購網資料包成的
MCP server，免註冊、免金鑰。**這正是 UNIT 6 教的接法**，所以有些組會想用它。

**用之前先知道五件事：**

1. **它只給個案，不給規章。** 期末驗收句要的「依據條號」仍然得自己從
   《政府採購法》建庫——它補的是輸入端，不是知識庫。
2. **回傳的招標方式不是標準答案。** 那是機關**實際採用**的方式，
   不代表合法。而且「分割採購規避法令」這一題最有意思的部分，
   **恰好不會顯示在公告裡**。
3. **預算金額是稀疏的。** 抽樣 10 筆只有 4 筆有預算金額，其餘要逐案再查。
4. **它有「推估」類的工具**（例如推估可能投標的廠商、投標行情）。
   那是用歷史資料訓練的模型推估，**不是機關的領標或投標名單**——
   拿它當事實寫進判定依據會出事。
5. **⚠ 使用條款禁止「以自動化程式大量擷取」，且網站沒有留聯絡方式。**
   互動式查詢沒問題；**批次抓資料建評測集會撞到這一條。**

> **本題的可行性評級不因此改變。** 手動從 `web.pcc.gov.tw` 取個案
> 仍是預設做法。這只是一個你可能會用到、但需要自己權衡的選項——
> **選了它，上面五件事要寫進提案表 §5（證據來源與取得方法）。**

**已查到的金額級距**（112 年 1 月 1 日起生效）

| 級距 | 金額 |
|---|---|
| 查核金額 | 工程／財物 **5,000 萬**；勞務 **1,000 萬** |
| 公告金額 | 工程／財物／勞務一律 **150 萬** |
| 中央機關小額採購 | **15 萬**以下 |

**預期難點**

1. **法條多、例外多。** 政府採購法本文加子法的條文量遠大於其他領域，
   要先劃定範圍（例如只做「招標方式判定」，不碰履約爭議）。
2. **分割採購規避法令的判定**是這一題最有意思的部分——
   機關不得意圖規避而分割採購，但「必要分割」經核准則以總額認定。
   這正需要主張與查核代理各自舉證。

**可行性：🟢 最高**——規章公開完整、判準是數字、且**有真實個案可用**。

> 規劃書原本就標註這一題「邏輯最硬」。若你們想把系統做紮實，這是首選。

## 領域 6｜個資蒐集告知與隱私衝擊初篩

**判定什麼**：某項蒐集行為的告知是否完備、蒐集目的是否相符。

| | |
|---|---|
| **判定邏輯特徵** | 告知義務、蒐集目的相符性 |
| **規章來源** | 《個人資料保護法》（全國法規資料庫）；《個人資料保護法之特定目的及個人資料之類別》（**182 項特定目的**，教育部與個資保護委員會籌備處法規系統皆有全文） |
| **個案來源** | **🟢 可用真實網站的隱私權政策**——公開、量大、品質參差正好 |

**已查到的判準核心：個資法第 8 條的告知六事項**

蒐集前應告知：**誰在蒐集／為何蒐集／蒐集哪些類別／如何使用**
（期間、地區、對象、方式）**／當事人有哪些權利／不提供的後果**。

這六項是法定義務，不是建議事項。

另需區分「特定目的**內**利用」與「特定目的**外**利用」，且須與蒐集時的特定目的相符。

**預期難點**

1. **「特定目的相符」的判定是主觀的**，182 項特定目的的歸類本身就有灰色地帶——
   這對多代理是優點（主張與查核容易分歧），但你們要能說明分歧怎麼收斂。
2. 隱私衝擊評估（PIA）在台灣**沒有統一的法定格式**，
   若要做 PIA 這一段，判定基準得自己定義並說明來源。

**可行性：🟢 高**——規章結構清楚（六事項是清單）、個案唾手可得。

## 選定領域之前，先做這三件事

在 11/11 提案之前，**實際動手**，不要只用想的：

1. **打開規章來源，確認你真的下載得到。** 網址失效、需要登入、只有紙本，都要當場發現。
   **並挑定你們要綁哪一套**（見上面「規章要綁在哪一個機構」）。
2. **找到或寫出一個具體個案。** 不是「某生申請實習」，是「某生已修 82 學分、
   實習 640 小時、投保學生團險、機構為 XX 公司」——**寫不出具體個案，就代表你還沒懂這個領域**。
3. **從規章裡找出三條會用到的條號。** 11/11 當場會被抽問其中一條的內容。

這三件事做完，提案表的 **§4 與 §5**（依據與判準、證據來源與取得方法）自然就寫得出來。

> **做第 1 件事的時候順手做一件事**：如果你們綁了兩套以上的來源，
> 記一下**它們在哪裡講得不一樣**。那一筆會直接變成提案表 §7 的失敗情境，
> 也是你們的查核代理真正要處理的東西。

## 需要注意的兩件事

**規章會改版。** 上面引用的金額級距、時數上限都標了生效日期，
但你們查的時候請**以來源網站的現行版本為準**，不要照抄本文件的數字。
「規章有兩個版本、代理引用到舊版」正是這類系統最典型的失敗，
也是你們在 HW1–HW2 已經踩過的坑。

**個案不得涉及可識別的真實個人**，完整規定見 `期中提案說明.md` 3.3
——那一條適用**所有**領域，不只領域 4 與領域 6。
